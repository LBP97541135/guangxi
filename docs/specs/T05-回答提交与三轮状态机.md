# T05 回答提交与三轮状态机

## 目标

实现回答提交和严格的三轮状态推进，保证用户不能跳题、倒退或因重复点击写入重复答案。

## 依赖

T04。

## 包含范围

- 实现 `POST /api/sessions/{session_id}/answers`。
- 校验请求轮次等于 Session 当前轮次。
- 校验快捷选项属于当前问题，或自由文本符合长度规则。
- 在一个数据库事务内保存 Answer 并推进 Session。
- 第一轮提交后进入 `QUESTION_2`。
- 第二轮提交后进入 `QUESTION_3`。
- 第三轮提交后进入 `GENERATING`。
- 第三轮后调用一个可替换的生成服务接口；本 Task 可使用 Fake 实现。
- 将数据库唯一约束转换为稳定业务错误。

## 排除范围

- 不实现真实模型客户端。
- 不编写 Prompt 或金句校验规则。
- 不实现动态追问、修改答案或回到上一题。
- 不实现 SSE 流式进度。
- 不允许前端直接指定下一状态。

## 状态迁移边界

```text
QUESTION_1 + round 1 -> QUESTION_2
QUESTION_2 + round 2 -> QUESTION_3
QUESTION_3 + round 3 -> GENERATING
其他组合 -> ROUND_MISMATCH 或 INVALID_SESSION_STATE
```

`COMPLETED`、`FAILED`、`GENERATING` 状态均不接受新答案。

## 交付物

- 回答提交 API。
- 三轮流程服务。
- Fake 金句生成服务接口。
- 状态迁移和并发/重复提交测试。

## 审核检测点

- [ ] 轮次判断在后端完成，不能信任前端状态。
- [ ] 保存答案和推进状态位于同一事务。
- [ ] 第一、二轮响应返回下一问。
- [ ] 第三轮只进入 `GENERATING` 并调用生成接口一次。
- [ ] 重复点击不会留下重复答案或跳过一轮。
- [ ] 非当前选项 Key 被拒绝。
- [ ] `COMPLETED/FAILED/GENERATING` 状态不能继续提交答案。

## 验收用例

1. 顺序提交三轮，数据库恰好存在三条 Answer。
2. 在第一轮提交 `round=2` 返回 `ROUND_MISMATCH`。
3. 提交其他问题的选项 Key 返回参数错误。
4. 同一轮提交两次，第二次返回 `ANSWER_ALREADY_EXISTS` 或等价稳定错误。
5. 两个并发请求提交同一轮，只有一个成功。
6. 第三轮完成后 Fake 生成服务只被调用一次。

## 完成定义

- 使用 Fake 生成服务可以跑通完整三轮。
- 所有合法和非法状态迁移均有测试。
- 数据库中不会出现跳轮或重复答案。
