# T08 端到端验收与交付

## 目标

验证整个 Demo 后端在正常与异常情况下都能完成演示，并向前端和部署人员提供可复现的运行方式。

## 依赖

T07。

## 包含范围

- 编写从创建会话到获得金句的端到端测试。
- 覆盖刷新恢复、重复提交、错误轮次、模型超时和失败重试。
- 校验 OpenAPI 中 5 个 P0 接口的请求响应。
- 完善 README、本地启动、测试和环境变量说明。
- 提供开发模式 Fake Provider 开关。
- 确认 SQLite 单机运行；若团队已决定公网 PostgreSQL，验证数据库切换。
- 提供最小演示部署配置或部署步骤。
- 准备模型不可用时的演示预案。

## 排除范围

- 不新增业务功能。
- 不在此 Task 修改三问、Prompt 风格或视觉表现。
- 不引入 Redis、消息队列、微服务或复杂 CI/CD。
- 不实现正式生产级高可用、自动扩缩容和多地域容灾。
- 不代替前端做浏览器端视觉验收。

## 交付物

- P0 端到端测试套件。
- API 契约检查。
- README 与 `.env.example` 最终版。
- Fake/真实模型运行说明。
- Demo 部署步骤。
- 演示前检查清单。

## 审核检测点

- [ ] 新环境按 README 可以启动，不依赖开发者机器上的隐式配置。
- [ ] Fake Provider 模式不联网即可跑通三轮。
- [ ] 真实 Provider 模式只需配置环境变量，不改代码。
- [ ] OpenAPI 路径、状态和错误格式与 Specs 一致。
- [ ] 重复提交、刷新恢复和失败重试均有端到端覆盖。
- [ ] 日志不包含模型 Key 和完整 Prompt。
- [ ] 本 Task 没有新增 P1 功能或基础设施。

## 端到端验收用例

### E2E-01 正常路径

1. 创建会话，得到第一问。
2. 提交第一轮，得到第二问。
3. 提交第二轮，得到第三问。
4. 提交第三轮，得到合规金句。
5. 再次查询会话，得到相同金句。

### E2E-02 刷新恢复

1. 完成第一轮。
2. 重新查询 Session。
3. 返回 `QUESTION_2` 和第二问，不丢第一轮答案。

### E2E-03 重复提交

1. 对同一轮发送两次相同请求。
2. 只保存一条 Answer，会话只推进一轮。

### E2E-04 模型失败恢复

1. 完成三轮并模拟模型连续失败。
2. Session 进入 `FAILED`，三轮答案仍在。
3. 恢复模型后调用重试接口。
4. Session 进入 `COMPLETED` 并返回金句。

### E2E-05 输出不合格

依次模拟空结果、错误前缀、超过 50 字和命中禁词，确认自动重试与最终失败边界正确。

## 演示前检查清单

- [ ] `/api/health` 返回正常。
- [ ] 数据库文件或连接可写。
- [ ] 模型 Key 和额度有效。
- [ ] Fake Provider 备用模式可用。
- [ ] 完整三轮真实请求至少成功一次。
- [ ] 前端使用的 API 地址正确。
- [ ] 演示录屏已准备，不依赖现场网络必然稳定。

## 完成定义

- 全部 P0 自动化测试通过。
- Reviewer 手工完成一次真实模型全链路。
- 新成员可以根据 README 在本地启动和测试。
- 前端可以基于 OpenAPI 完成最终联调。
- 演示环境与备用方案均通过检查。
