# T07 金句生成与失败恢复

## 目标

把三轮会话链路和模型链路汇合，可靠地产生、校验、保存并返回唯一金句；失败时保留回答并允许重试。

## 依赖

T05、T06。

## 包含范围

- 实现金句生成协调服务。
- 从数据库读取并确认三轮答案齐全。
- 调用 `QuoteProvider` 获得候选金句。
- 校验非空、前缀、50 字限制和禁词。
- 模型超时或输出不合格时自动重试一次。
- 成功时保存 Quote，并将 Session 改为 `COMPLETED`。
- 两次失败后将 Session 改为 `FAILED`，保留全部 Answer。
- 实现 `POST /api/sessions/{session_id}/retry`。
- 第三轮回答接口接入真实生成服务并返回完整金句。

## 排除范围

- 不实现 SSE 或逐字输出。
- 不实现备用模型和无限重试。
- 不生成卡片图片。
- 不实现分享、图鉴和用户反馈。
- 不做心理诊断或人格分类。
- 不对已完成会话重新生成另一条金句。

## 校验边界

候选金句必须同时满足：

1. 非空。
2. 以“其实，你”开头，后面可接逗号或省略号。
3. 按团队冻结的计数规则不超过 50 字。
4. 不包含 MBTI 类型、九型人格、星座等禁词。
5. 不出现“你属于某类人”等分类式表达。

## 重试边界

- 一次用户生成动作最多调用模型两次。
- 自动重试仍失败后必须停止并返回 `GENERATION_FAILED`。
- 只有 `FAILED` 会话能调用手动重试接口。
- `COMPLETED` 会话查询或重复请求始终返回原 Quote。

## 交付物

- 金句校验器。
- 生成协调服务。
- 自动重试逻辑。
- 手动重试 API。
- 第三轮完成后的真实生成集成。
- 成功、失败、恢复和幂等测试。

## 审核检测点

- [ ] 三轮答案不完整时绝不调用模型。
- [ ] 每次自动生成最多调用模型两次。
- [ ] 校验失败原因可从日志或测试结果辨识。
- [ ] Quote 保存和 Session 完成状态处于同一事务。
- [ ] 失败时三轮 Answer 完整保留。
- [ ] `COMPLETED` 会话不会生成第二条 Quote。
- [ ] API 只返回最终金句，不返回 Prompt 或模型原始对象。
- [ ] 前端可以仅用 `retryable` 和错误码决定是否显示重试。

## 验收用例

1. 首次输出合格：调用模型一次，保存一条 Quote，状态为 `COMPLETED`。
2. 首次不合格、第二次合格：调用两次，只保存第二条结果。
3. 两次均不合格：状态为 `FAILED`，无成功 Quote，三条 Answer 仍存在。
4. 模型超时后自动重试一次，仍超时则返回稳定错误。
5. `FAILED` 会话手动重试成功后进入 `COMPLETED`。
6. `COMPLETED` 会话调用重试接口返回状态冲突，不产生新 Quote。
7. 禁词、超长、错误前缀和空结果分别被拒绝。

## 完成定义

- 真模型与 Fake 模型都能跑通生成链路。
- 每个成功会话只有一条合规 Quote。
- 每个失败会话可恢复且不丢答案。
- 重试次数边界有自动化测试保证。
