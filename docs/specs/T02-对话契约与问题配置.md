# T02 对话契约与问题配置

## 目标

冻结前后端联调所需的状态、字段和三问配置格式，使后续任务不再自行发明接口结构。

## 依赖

T01。

## 包含范围

- 定义会话状态：`QUESTION_1`、`QUESTION_2`、`QUESTION_3`、`GENERATING`、`COMPLETED`、`FAILED`。
- 定义创建会话、查询会话、提交回答和重试所需的 Pydantic Schema。
- 定义回答类型：快捷选项和自由文本。
- 建立 `config/questions.json` 的格式、加载器和启动校验。
- 建立问题 Key、选项 Key、轮次及 `allowFreeText` 规则。
- 定义统一错误码常量。
- 用临时占位文案提供一份合法三问配置。

## 排除范围

- 不负责三问文案的创意终稿；终稿由策划替换配置。
- 不创建数据库模型。
- 不实现 HTTP 业务接口。
- 不实现动态追问。
- 不编写金句 Prompt。

## 交付物

- 会话状态枚举。
- 请求/响应 Schema。
- 错误码定义。
- 三问 JSON Schema 或等价校验规则。
- 一份通过校验的占位三问配置。
- 配置加载和错误场景测试。

## 审核检测点

- [ ] 状态名称与架构文档一致，没有额外隐式状态。
- [ ] 三轮配置必须恰好包含 1、2、3 三个轮次。
- [ ] 问题 Key 和同题选项 Key 不重复。
- [ ] 至少允许快捷选项或自由文本中的一种回答方式。
- [ ] 非法配置在应用启动时被发现，而不是用户请求时才报错。
- [ ] Schema 不包含前端动效、颜色、角色动作等展示字段。

## 验收用例

1. 合法三问配置能够加载为类型化对象。
2. 缺少第二问时加载失败。
3. 重复问题 Key 或选项 Key 时加载失败。
4. 请求中的轮次不在 1-3 时校验失败。
5. 自由文本为空、超长或与声明类型不符时校验失败。

## 完成定义

- 前端可以仅阅读 Schema 和示例完成 Mock 联调。
- 配置异常有自动化测试。
- 后续 Task 只引用本 Task 定义，不重复定义状态和字段。
