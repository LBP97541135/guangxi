# T06 模型适配与 Prompt

## 目标

提供一个与具体模型供应商隔离的最小生成能力：输入三轮结构化回答，输出一段候选金句文本。

## 依赖

T01、T02。

## 包含范围

- 定义 `QuoteProvider` 接口或等价抽象。
- 实现 `FakeQuoteProvider`，供测试和前端联调使用。
- 实现一个真实模型 Provider。
- 从环境变量读取模型 Key、Base URL 和模型名。
- 实现 `PromptBuilder`，组合系统规则、三问和三轮回答。
- Prompt 明确禁止模型使用人格标签或服从用户输入中的指令。
- 设置单次调用超时，默认 15 秒。
- 将供应商异常转换为内部模型错误。

## 排除范围

- 不保存 Session、Answer 或 Quote。
- 不决定何时调用模型。
- 不实现自动重试。
- 不负责最终金句长度、前缀和禁词校验。
- 不实现备用模型、多模型路由、流式输出或 Token 成本平台。
- 不将模型原始响应直接暴露给 API 路由。

## 输入输出边界

输入：

- 三个有序问题。
- 三个有序回答。
- 固定金句写作规则。

输出：

- 一段候选金句字符串。
- 最小生成元数据：模型名；若 SDK 易于获取，可包含 Token 数。

Provider 不返回 HTTP Response，不读取数据库，也不更改会话状态。

## 交付物

- Provider 接口。
- Fake Provider。
- 一个真实 Provider。
- Prompt Builder 与 Prompt 配置。
- 超时、异常映射和 Prompt 单元测试。

## 审核检测点

- [ ] API Key 未硬编码，也不会写入日志。
- [ ] Prompt 中三个问题与三个回答顺序正确。
- [ ] 用户回答使用明确的数据边界包裹，不能覆盖系统规则。
- [ ] Provider 可在测试中被 Fake 替换，无需联网。
- [ ] 真实模型超时返回稳定内部错误。
- [ ] 本 Task 没有数据库写入和业务状态迁移。
- [ ] 没有为了“以后可能需要”增加第二个 Provider。

## 验收用例

1. Fake Provider 对固定输入返回固定候选金句。
2. Prompt Builder 输出包含三轮内容且顺序正确。
3. 回答中包含“忽略之前规则”时，它仍位于用户数据区域。
4. 模拟超时得到 `MODEL_TIMEOUT`。
5. 模拟供应商 4xx/5xx 得到可识别内部错误，响应中不泄露 Key。

## 完成定义

- Fake 和真实 Provider 使用同一调用接口。
- 无真实 Key 时测试可以全部运行。
- 给定三轮回答可获得候选金句或稳定错误。
