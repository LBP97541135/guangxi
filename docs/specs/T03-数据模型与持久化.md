# T03 数据模型与持久化

## 目标

实现 Session、Answer、Quote 三张业务表及最小数据访问能力，为会话恢复和结果保存提供可靠基础。

## 依赖

T01、T02。

## 包含范围

- 配置 SQLAlchemy Engine 和数据库 Session。
- 本地默认使用 SQLite；通过 `DATABASE_URL` 保留 PostgreSQL 切换能力。
- 创建 `Session`、`Answer`、`Quote` 三个 ORM 模型。
- 实现建表或最小迁移方案。
- 提供创建/查询会话、保存/查询答案、保存/查询金句所需的数据访问函数。
- 建立唯一约束：`Answer(session_id, round_no)`、`Quote(session_id)`。
- 为状态推进保留事务边界。

## 排除范围

- 不实现 HTTP 路由。
- 不实现三轮业务状态迁移。
- 不调用模型或校验金句。
- 不创建 Question 或 Prompt 数据表。
- 不做通用 Repository 框架或复杂基类。

## 数据边界

### Session

- `id`
- `status`
- `current_round`
- `created_at`
- `updated_at`

### Answer

- `id`
- `session_id`
- `round_no`
- `answer_type`
- `option_key`（可空）
- `content`（可空，取决于回答类型）
- `created_at`

### Quote

- `id`
- `session_id`
- `content`（生成成功前可空）
- `model`
- `generation_attempts`
- `status`
- `created_at`

## 交付物

- 数据库配置。
- 三个 ORM 模型。
- 初始化/迁移能力。
- 最小数据访问函数。
- SQLite 集成测试。

## 审核检测点

- [ ] 三张表字段与 Spec 一致，没有提前增加用户、分享、图鉴字段。
- [ ] 外键关系正确，删除或孤儿数据策略明确。
- [ ] 同一会话同一轮答案无法重复插入。
- [ ] 同一会话无法保存两条 Quote。
- [ ] 数据访问函数不包含 HTTP 和模型调用逻辑。
- [ ] SQLite 测试库与开发库隔离。

## 验收用例

1. 创建 Session 后可以按 ID 查询。
2. 一个 Session 可以保存三轮不同 Answer。
3. 保存相同 `session_id + round_no` 的第二条 Answer 触发唯一约束。
4. 同一 Session 保存第二条 Quote 触发唯一约束。
5. 事务失败后不留下半条 Answer 或错误状态。

## 完成定义

- 三张表可在空数据库中创建。
- 数据唯一性由数据库保证，而不是只依赖 Python 判断。
- 所有持久化集成测试通过。
