# T04 会话创建与恢复 API

## 目标

实现匿名会话的创建和查询，使前端进入对话时能获得第一问，并在页面刷新后恢复正确进度。

## 依赖

T02、T03。

## 包含范围

- 实现 `POST /api/sessions`。
- 实现 `GET /api/sessions/{session_id}`。
- 创建会话时设置 `QUESTION_1` 和 `current_round=1`。
- 从问题配置读取并返回当前问题及快捷选项。
- 根据状态返回当前问题、生成状态、失败状态或最终金句。
- Session ID 使用不可预测的 UUID。
- 实现 `SESSION_NOT_FOUND` 统一错误。

## 排除范围

- 不提交或保存回答。
- 不推进会话轮次。
- 不调用大模型。
- 不实现登录、Cookie 账号或设备绑定。
- 不实现会话列表和历史图鉴。

## API 边界

### `POST /api/sessions`

返回：

- `sessionId`
- `status=QUESTION_1`
- `currentRound=1`
- 第一问及选项

### `GET /api/sessions/{session_id}`

- `QUESTION_1-3`：返回当前问题。
- `GENERATING`：返回状态，不返回虚构进度百分比。
- `FAILED`：返回可重试状态。
- `COMPLETED`：返回唯一金句。

## 交付物

- 两个 API 路由。
- 会话应用服务。
- OpenAPI 示例。
- API 集成测试。

## 审核检测点

- [ ] 新建会话一定从第一轮开始。
- [ ] 响应问题来自配置文件，不在路由中硬编码。
- [ ] 查询不会修改会话状态或创建新数据。
- [ ] 不存在的 UUID 返回 404 和 `SESSION_NOT_FOUND`。
- [ ] 返回字段中没有数据库内部对象或模型密钥。
- [ ] 刷新恢复所需信息完整，前端无需猜测下一步。

## 验收用例

1. 创建会话返回 HTTP 201、第一问和唯一 Session ID。
2. 连续创建两次得到两个不同 Session ID。
3. 查询新会话返回第一问。
4. 查询不存在会话返回统一 404。
5. 通过测试预置不同状态，查询分别返回正确响应形态。

## 完成定义

- 前端可完成“进入对话”和“刷新恢复”的 Mock 联调。
- 两个接口的成功与错误路径均有测试。
- 本 Task 未写入回答或模型逻辑。
